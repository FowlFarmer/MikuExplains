# AGENTS.md

## Project Direction

- Miku Explains still includes the legacy native macOS Swift menu bar app built with Swift Package Manager. The Swift package/target/executable path now uses `MikuExplains` internally.
- The first prototype prioritizes reliable selected-text capture with clipboard copy/restore.
- Real AI calls run through the local Codex CLI, hosted Gemma 4 through Google's Gemini API, or the managed llama.cpp backend. When text is found, Miku Explains saves it, asks the selected backend to infer the user's likely intent, and writes a tagged JSON result made of dynamic UI items.

## Current UX

- The app runs as an accessory/menu bar app with no Dock icon.
- The packaged app bundle identifier is `com.mikuexplains.app`. Keep this stable; changing it can cause macOS Accessibility and Keychain trust prompts to come back.
- The app is branded as `Miku Explains`, uses `Resources/miku_crop.png` as a rounded-square menu bar icon, uses `Resources/AppIcon.icns` as the bundle app icon generated from that same crop, and renders `Resources/miku.png` as a large transparent sticker in the React UI. The borderless window includes transparent top-left overhang space so the sticker can sit outside the panel without clipping. Content must stay inside the card/header layout so text never draws over the sticker.
- The React panel was rebuilt from first principles after the AppKit UI migration. Treat `Resources/WebUI/app.js` and `Resources/WebUI/styles.css` as the source of truth for all visible UI: fixed transparent stage, floating sticker, imperfect paper shell, masthead, state body, hand-drawn item cards, history rows, fake loading meter, and debug drawer.
- The Miku sticker wiggles when React enters the history list, receives a loading completion token, or a result card header appears. During local-model streaming, body-token updates must not retrigger the wiggle; `Resources/WebUI/app.js` keys result wiggles from the card header signature (`index:type:title`) only. The animation is implemented by remounting the sticker with a changing React key and applying the `miku-wiggle` CSS keyframes. All sticker images are positioned from a center anchor so `miku.png`, `miku_sleep1.png`, and `miku_sleep2.png` align despite different PNG dimensions. The sticker CSS must keep explicit rendered width/height boxes, and React must keep PNG width/height attributes, so WebKit never first-paints a zero-height image that snaps after decode. When the panel is unfocused, React swaps the sticker from `miku.png` to 82%-sized `miku_sleep1.png` / `miku_sleep2.png`, alternating 2.5s on sleep1 and 1s on sleep2 until focus returns. The unfocused sleeping sticker may desaturate, but it should stay fully opaque; only sleep2 is raised 3px and rendered 1% larger than sleep1 to visually line up.
- The default shortcut is `Command + Shift + Space`, displayed in the React toolbar as `shortcut: ⌘⇧Space`. Clicking that toolbar button opens an in-panel shortcut recorder page; successful captures update the Carbon global hotkey immediately and persist the shortcut in `UserDefaults` under `MikuExplainsShortcut`.
- The macOS menu bar/tray icon dropdown includes `Past Summaries`, which opens the verified history list directly. The in-panel model selector should stay focused on model choice and downloads only.
- The toolbar model pill is right-anchored before the shortcut/debug/close controls. Keep its right edge fixed and let longer model labels grow/truncate leftward so it never pushes the right-side controls.
- The in-panel model selector includes one hosted Gemma option: `google:gemma-4-26b-a4b-it`, displayed as `Gemma 4 MoE`. The retired `google:gemma-4-31b-it` tag aliases to this model but should not appear in the UI. Selecting the Gemma API row reveals a compact Gemini API key form. The token is never sent back to React after saving; React only receives `geminiAPIKeyConfigured` so it can show `needs key` or `api` state. `GeminiAPIKeyStore.swift` stores the token directly in Keychain as a normal generic password under service `com.mikuexplains.app`, migrates the old `app.miku-explains.prototype` Keychain item, and cleans up the retired encrypted Application Support token file if it sees one. Do not add `SecAccessControl`, user-presence, biometric, or device-passcode requirements for this token unless the user explicitly wants repeated prompts. Because normal AppKit edit-command routing can be brittle inside the borderless `WKWebView` accessory app, the key input has a Swift pasteboard bridge for `Command+V` / `Control+V` and a `paste` button. Selecting a Gemma model with no key should not call `showMessage`; it should keep the current page and use debug/toast state only.
- Pressing the global shortcut while the panel is already visible first checks the current selected text with the clipboard capture path: if nothing is selected, the panel closes; if the selected text matches the last captured text, the panel closes; if the selected text is different, Miku Explains starts a fresh pipeline for the new selection. Pressing the menu bar `Explain Selection` item still starts capture directly.
- The app asks macOS for Accessibility permission when it launches.
- When the panel is closed, pressing the global shortcut opens the React panel immediately in a `Reading` loading state before clipboard capture begins, so users get instant feedback instead of waiting on pasteboard polling. Miku Explains preserves the current pasteboard, clears it to avoid stale captures, sends `Command + C`, waits up to 0.5s for copied text, restores the pasteboard, and then starts the smart inference flow. If no text is copied, it opens the past results list.
- Each successful capture is saved as raw Markdown text under `~/Library/Application Support/MikuExplains/Captures/` using a nearest-second timestamp filename like `yyyy-MM-dd_HH-mm-ss.md`; same-second collisions receive a numeric suffix.
- After capture persistence, `SummaryPipeline` invokes the selected inference backend through `InferenceBackendRouter`. `codex` uses the Codex CLI; `google:gemma-4-26b-a4b-it` uses hosted Gemma 4 MoE through Google's Gemini API with a Keychain-stored API key or `GEMINI_API_KEY` / `GOOGLE_API_KEY`; every other supported model tag uses llama.cpp. Ollama has been removed from the app. Backends share the strict JSON result parser in `AIResult.swift`, but `InferencePromptBuilder.swift` uses smaller non-Codex prompt schemas: llama.cpp and Gemma API emit `tagline`, `primary_intent`, confidence, and `items` only, while Codex may also emit web-search flags for its second verification pass. Missing web-search flags decode as false. The prompt treats English as the preferred output language and treats non-English selected text as a strong translation-to-English intent. llama.cpp and Gemma API never request web search. The Codex path remains the only web-search-capable option. The final result is saved as `[timestamp]-[tagline]-result.json`. Old JSON using `cards` and old `[timestamp]-[tagline]-summary.md` files remain readable as legacy result records.
- Result items may include an optional `tool` payload. The first supported tools are `calendar.create_event` and `reminders.create_reminder`, executed by `MikuToolExecutor.swift` through EventKit only after the user clicks the card's accept button in React. The prompt includes the current local date/time/timezone so vague dates such as "Tuesday" can resolve to the next future occurrence. Tool params should use concrete local ISO 8601 strings with timezone offsets. The packaged app Info.plist must include Calendar and Reminders usage descriptions.
- Weak local models sometimes put pseudo tool calls such as `calendar.create_event params: {...}` in the visible card body instead of emitting a separate `tool` object. `AIResult.swift` intentionally has a salvage path that extracts those pseudo calls, tolerates null/non-string param values, attaches a real `AIResultTool`, and replaces the raw body with a human-readable sentence so React can show the accept button.
- Local llama.cpp inference streams through OpenAI-compatible SSE (`stream: true`, `max_tokens: 1024`, `cache_prompt: true`) in `LlamaCppSummarizer.swift` and asks llama-server for JSON mode with `response_format: {"type":"json_object"}`. Hosted Gemma 4 inference uses Google's documented Gemma-on-Gemini `generateContent` endpoint in `GeminiAPISummarizer.swift`, waits for the final candidate text before parsing cards, caps output at 1024 tokens, and uses a 45-second hard request timeout with debug lines for endpoint, thinking policy, waiting state, HTTP status, response bytes, network errors, and returned character count. Gemma 4 documents thinking as an on/off toggle rather than medium/high effort levels, so `GeminiAPISummarizer.shouldEnableThinking` omits `thinkingConfig` for lightweight selections and sends the supported `thinkingConfig.thinkingLevel = "high"` only for longer or more complex selections. When Gemma thinking is enabled, Swift sends a dedicated thinking-started callback so React shows the shared `InferenceStatus` placeholder as `Thinking.` / `Thinking..` / `Thinking...` in the same body position used while local streamed card content is not parseable yet. `LlamaCppManager.swift` launches llama-server with `--cache-prompt`, `-np 1`, and an 8192-token context, so the single local slot can reuse KV for shared prompt prefixes. `InferencePromptBuilder.swift` uses an ordered key contract for local prompts instead of copyable placeholder JSON values; keep the stable instruction prefix before the changing date/hints/highlighted text so llama.cpp prompt caching can reuse the instructions across requests. Do not reintroduce literal placeholder examples such as `"tagline": "1 to 4 words"` into the llama.cpp branch. `StreamingJSONResultParser.swift` incrementally scans the deterministic JSON output for llama.cpp only: once complete `tagline` and `primary_intent` strings are available, Swift moves the React panel to the result screen; then it reads the single `items` array directly. When an item has complete `type` and `title` fields and its `body` string has started, that card appears and updates as more tokens arrive. The active prompt forbids `card_headers`, `card_plan`, `cards`, or duplicate header arrays; `ParsedCodexSummary` still accepts those legacy keys only for old saved results or salvage. Both the streaming parser and final `ParsedCodexSummary` sanitizer treat copied prompt placeholders such as `1 to 4 words`, `REAL_SHORT_LABEL`, `BEST_INTENT`, `CARD_TYPE`, and `ANSWER_TEXT` as empty/bad values. Disk persistence/history prefer the final complete JSON parse through `ParsedCodexSummary`. If llama.cpp stops mid-JSON after cards have streamed, Swift saves those streamed partial cards with a low-confidence cutoff note and logs the finish reason, instead of replacing them with an instruction-failure card. If a weak/local/hosted model returns prose instead of JSON and no cards can be salvaged, Swift wraps the raw response in a low-confidence `note` card titled `Instruction failure`, explicitly says the model failed to follow the required JSON format, and saves it instead of failing the pipeline.
- llama.cpp inference runs through `llama-server` downloaded from the latest llama.cpp GitHub release into `~/Library/Application Support/MikuExplains/Models/llama-server-runtime/` on first local-model pull or first local inference, with a pinned fallback release tag for offline installs. The whole runtime directory is preserved because current macOS llama.cpp binaries depend on sibling `.dylib` files via `@loader_path`. The release URL is resolved at install time via the GitHub Releases API and tracks upstream renames of the binary archive. The server speaks the OpenAI-compatible `/v1/chat/completions` protocol on a persisted random localhost port recorded in `llama-server.port`, overridable with `MIKU_LLAMACPP_BASE`. The server is spawned in the background at app launch (and again on model switch) so it stays warm for the lifetime of the app. It is terminated on app exit and reaped across relaunches via a PID file.
- llama.cpp model pulls go through a curated registry in `LlamaCppManager.modelRegistry` that maps UI tag names (e.g. `qwen3:4b`) to Hugging Face `repo + .gguf file` pairs. Swift sends this catalog to React through the panel state bridge; the hardcoded React preset list is only a boot-time fallback before the bridge is ready. Keep filenames exact and case-sensitive: Qwen 3.5 2B uses `unsloth/Qwen3.5-2B-GGUF` with `Qwen3.5-2B-Q4_K_M.gguf`, Qwen3 4B uses `Qwen3-4B-Q4_K_M.gguf`, and the retired `qwen3:1.7b` saved preference aliases to `qwen3.5:2b`. Llama 3.2 1B was removed from the selectable registry after repeated instruction/schema-following failures; if a user previously saved that tag, `AppDelegate.loadModel()` falls back to `codex` because the tag is no longer in `modelRegistry`. Pulls are single-shot downloads into a temporary URLSession file and atomically moved to `model.gguf` on success. Download status uses `URLSessionDownloadDelegate.didWriteData` for byte counts, falls back to the curated registry size when Hugging Face does not expose a total, and emits compact labels such as `37% 920M/2.5G` so the model dropdown row stays stable.
- Summarization is guarded by `SummaryPipeline`: an in-memory token blocks repeated shortcuts in the running app, and `~/Library/Application Support/MikuExplains/summarization.lock` blocks duplicate queries across relaunches. The lock is created before clipboard capture, updated to the Codex child PID or `0` for in-process local backends, released on success/failure, and considered stale if the owner process is gone or the lock is older than six hours.
- llama.cpp pull state is **not** crash-resumable: each model directory contains only the final `model.gguf` (or nothing during a pull). The download is a single-shot `URLSession.downloadTask` with a 2-hour timeout; on failure URLSession auto-cleans the temp file, on success it is atomically moved to `model.gguf`. A network blip or force-quit means the user re-pulls the model from scratch. No partial files, no `state.json`, no `Range` requests, no SHA verification.
- Capture is delayed very briefly after the global hotkey so the original `Command + Shift + Space` modifiers are released before Miku Explains sends `Command + C`.
- Results appear in a fixed-size top-right whimsical pastel React panel hosted inside a transparent `WKWebView`, instead of a full-screen overlay or hand-built AppKit controls. The panel currently uses a 570x620 transparent borderless window with a 40px right margin and smaller 14px top margin; the visible card is inset within that window to leave room for the sticker overhang.
- The `WKWebView` transparency is part of the UI contract: `drawsBackground` must be false, the web view/layers must be non-opaque, and WebKit child views are cleared after navigation finishes. If this regresses, the symptom is a white rectangular window behind the React panel.
- Avoid broad external colored shadows on the shell or sticker because they clip against the transparent WebKit window bounds and create abrupt color cutoffs. Keep pink/teal washes inside the shell or use tight, non-bleeding shadows.
- Every panel transition resets the window to a freshly computed top-right frame on the visible screen, then lays out and reapplies that frame, to prevent history-to-detail navigation from drifting into the screen edge.
- Swift owns only the native shell/window position and sends JSON state into React. React sends events back through `window.webkit.messageHandlers.mikuPanel` for `ready`, `close`, `back`, `toggleDebug`, `selectHistory`, `openShortcutSettings`, and `recordShortcut`.
- Swift also owns panel focus state through `NSWindow.didBecomeKeyNotification` / `didResignKeyNotification` and sends `isFocused` into the React state. React applies `stage is-focused` or `stage is-unfocused`; CSS should express inactive state with subtle dimming/desaturation and weaker sketch/shadow treatment without moving layout or hurting readability.
- The result panel updates its React state before ordering the window onscreen, and only fades in when first opened; in-panel page changes should not reset alpha or re-order the window.
- The detail page shows dynamic AI result item cards, not the captured source text. It can show only a definition, or multiple items such as summary, assumptions, actions, validity, web context, numerical sanity, contrarian analysis, translation, or code help.
- Result items are rendered by React as separate pastel Miku note scraps inside a vertical scroll area. They should look unfinished and hand-drawn: uneven paper corners, crooked sketch outlines, tape marks, rough marker accents, and marker-like titles. Do not rotate the whole `answer-card` layout box; long cards make whole-card angles compound and drift. Keep content upright and express the handmade slant through corner-pinned paper/outline polygons, tape elements, and clipped left marker rails. Card tape placement alternates right/left, starting with the first card taped at the top right. Avoid polished SaaS cards, smooth pill accents, or clean circular rounded-rectangle borders. Card colors are selected from a small type catalog, and unknown types are canonicalized to `note`.
- While Codex is running, the detail page shows only a fake circular progress ring using a `1 - e^-t` style curve; it eases to 100% before the summary appears.
- If Codex enters the second web-search verification pass, the loading UI switches to a `Verifying` phase with a green ring, green percent text, and `Searching web` caption.
- Validity analysis is no longer a hardcoded slot; it appears only when Codex returns a validity card.
- The main panel UI should be edited in React/CSS, not AppKit. It uses a soft Miku-inspired palette: pale mint/pink gradient paper, teal ink accents, pink sketch accents, rounded/marker-like fonts, a dedicated masthead composition, and a large `miku.png` sticker illustration.
- The React/CSS interaction layer includes lightweight hover, press, focus-visible, dropdown-pop, loading-breathe, listening-pulse, and model-progress shimmer animations for buttons, cards, history rows, the shortcut recorder, and model controls. Keep these mostly transform/opacity/background based and honor `prefers-reduced-motion`.
- The history list is rendered by React as simple date-plus-tagline text rows on the pastel panel, with no AppKit button chrome. Do not re-add a repeated right-side intent/result label; it crowds the scrollbar and does not communicate useful information. Keep a small top offset in the history scroll area so the large Miku sticker does not cover the first saved row.
- History timestamps use a compact format like `May 19, 2:14 AM` so the time fits in the React history row.
- The debug area is controlled by a compact toolbar pill labeled `debug` and is off by default. When enabled it logs the full capture pipeline: source, character count, capture path, raw output path, backend launch, backend startup progress, and backend success/failure. Successful llama.cpp runs also append a compact runtime stats block parsed from `llama-server.log`, including Metal/device evidence, context size, prompt eval speed, generation speed, and total time.
- The back arrow opens a history page of verified results. History uses `summary-index.json` as a manifest for saved result metadata, merges it with filename scanning for legacy `*-result.json` and `*-summary.md` files, verifies the matching pre-result `[timestamp].md` capture exists, and repairs the index opportunistically.
- Opening history is optimized with an in-memory cache warmed at launch. Refreshes scan filenames and the manifest, verify matching captures with an in-memory filename set, and load result JSON or legacy summary Markdown lazily when a history row is selected.
- Avoid rebuilding panel visuals in AppKit; the Swift panel should remain a `WKWebView` state bridge unless native OS behavior is required.
- The panel does not auto-hide; it stays open until the user closes it with the `×`, quits the app, or Miku Explains replaces it with another panel state.

## Known Limits

- Some apps may block copied selection or require focus to remain in the selected text surface.
- Full Xcode project files are not checked in; open the package in Xcode or build with `swift build`.
- `scripts/package_app.sh` creates and ad-hoc signs `dist/Miku Explains.app` with `LSUIElement` enabled so macOS treats it as a menu bar style app. It copies `Resources/miku.png`, `Resources/miku_crop.png`, `Resources/AppIcon.icns`, and `Resources/WebUI/` into `Contents/Resources`, and sets `CFBundleIconFile` to `AppIcon`. `llama-server` is **not** bundled; the full llama.cpp runtime is downloaded at runtime into `~/Library/Application Support/MikuExplains/Models/llama-server-runtime/`, resolved from the latest GitHub release via the Releases API (with `LlamaCppManager.fallbackLlamaCppReleaseTag` as a pinned offline fallback).
- `scripts/dev.sh` is intentionally destructive: it kills `MikuExplains`, stops any managed llama.cpp server using `~/Library/Application Support/MikuExplains/Models/llama-server.pid` plus app-scoped command-line matches, deletes `~/Library/Application Support/MikuExplains`, deletes legacy `~/Library/Application Support/Denebula` if present, resets saved defaults and Accessibility permission for `com.mikuexplains.app` plus the legacy `app.miku-explains.prototype`, rebuilds, packages, and relaunches the app.
- macOS Accessibility permission can become stale after rebuilding unsigned prototype apps. Prefer testing through `dist/Miku Explains.app`; if System Settings shows permission but `AXIsProcessTrusted()` fails, remove Miku Explains from Accessibility, relaunch the rebuilt app, and add it again.
